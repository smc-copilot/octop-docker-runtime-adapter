## 实机验证边界

本次没有连接、修改或重启业务服务器，也没有拿到“超级助手.zip”的实际内容。Docker 和 systemd 生命周期使用测试替身，PostgreSQL 没有真实数据库验收。原现场 REPORT 的实机通过结论仅对应原功能，不能用来替代新增功能的实机验收。

部署后先用 `--agent-id BDZ8X1` 等单一测试员工专家进行维护窗口验收：查看模板查询、挂载清单、ZIP hash、文件覆盖及保留、容器 ID 不变、Skills/子智能体加载、代表性 Python 任务；确认后再扩大批量目标。

## 已知运行条件

- 整包 overlay；不删除 ZIP 之外的目标文件、不安装 Python 依赖、不改写脚本中的绝对路径。
- 工作区应无符号链接、硬链接、套接字等特殊文件；遇到此类文件明确失败，不静默跳过。
- 需要可用磁盘容纳批次备份、展开 ZIP 和单目标暂存副本。
- 依赖 Linux 文件系统原子目录交换；不支持时失败而不是降低原子性。
- `--stop-runtime` 会暂停本实例所有员工的 Octop 服务，以及目标用户的共享容器；需要事先排空任务。
- 批次逐专家提交，不具备跨专家事务；报告明确记录已成功目标，支持整批回滚。
- 无自动清理历史备份、无后台任务排空、无业务任务自动续跑、无新增 Web 页面或端口。
- 旧现场 profile/基线问题保持原维护策略；本工具不会为了继续恢复而绕过身份、版本或挂载校验。
